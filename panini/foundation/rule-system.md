# Rule System та Вирішення Конфліктів

Цей документ формалізує принципи застосування правил (sūtras) у граматиці Паніні, з особливим акцентом на те, як вирішуються конфлікти, коли два правила намагаються застосуватися одночасно.

## [PANINI]
У граматиці Паніні часто виникають ситуації, коли одне слово відповідає умовам одразу двох правил (tulya-bala-virodha).
Для таких випадків існують два основні механізми:
1. **Apavāda (Виняток):** Спеціальне правило (`apavāda`) завжди перемагає загальне правило (`utsarga`). Загальне правило блокується там, де діє виняток, і застосовується лише у залишковому просторі.
2. **Vipratiṣedha (Суперечність):** Визначається сутрою 1.4.2 (*vipratiṣedhe paraṃ kāryam*). Якщо два правила однакової сили конфліктують, застосовується те правило, яке знаходиться **пізніше (para)** у порядку Aṣṭādhyāyī (має вищий порядковий номер). 

Крім того, є поняття **Asiddha** (8.2.1): правила з останніх трьох чвертей граматики (Tripādī) вважаються "неіснуючими" для попередніх правил (Sūtra 8.2.1 *pūrvatrāsiddham*). Це означає, що результати правил Tripādī не можуть бути тригером для правил із перших 7.25 глав.

## [INTERPRETATION]
Це класична система Rewrite Rules, яка дуже схожа на сучасні експертні системи або Production Rule Systems. `Vipratiṣedha` діє як механізм пріоритетів, а `Asiddha` гарантує відсутність нескінченних циклів (infinite loops) при застосуванні рекурсивних правил і діє як бар'єр одностороннього водоспаду (waterfall pipeline).

## [MY-LISP HYPOTHESIS]
У `My Lisp` ми можемо змоделювати це за допомогою **Inference Engine** (Двигуна логічного виведення) або **Finite State Transducer (FST)**.
Замість того, щоб жорстко кодувати логіку `if-else` у функції, ми визначимо кожну сутру як незалежний об'єкт:
```lisp
(def-rule sutra-1-4-2
  (pattern ...)
  (action ...))
```
Наш двигун (Inference Engine) триматиме всі правила у граматичному графі (Rule Graph). Коли виникає конфлікт (декілька правил match'ать один і той самий стан), двигун використовує алгоритм вирішення конфліктів (Conflict Resolution Strategy), заснований на:
1. Перевірці відношення *utsarga-apavāda* (специфічність паттерну).
2. Порівнянні індексів правил (sutra index) для імплементації *vipratiṣedhe paraṃ kāryam*.
3. Ізоляції фаз (Tripādī як окремий Pipeline етап, який не повертається назад).
